# الثعبان التنافسي — Battlesnake Policy/Value Engine

هذا المستودع يضم وكيل **Battlesnake** متعدد الطبقات، مهيأ للتطوير من منطق تكتيكي قوي ومفسَّر إلى نموذج سياسة/قيمة مدرّب باللعب الذاتي. لا يَعِد المشروع بأنه «لا يُهزم»؛ الفوز الفعلي يتطلب تدريباً كافياً وتقييماً ضد خصوم المسابقة وخريطة المسابقة النهائية. لكنه يضع أساساً قابلاً للتكرار يمنع الأخطاء القاتلة الواضحة قبل أن يسمح للنموذج المتعلم بالتأثير في القرار.

> في Battlesnake تُحل الحركات بصورة متزامنة؛ الثعبان الأطول فقط ينجو في اصطدام الرأس بالرأس، كما يتحرك الذيل قبل نمو الطعام. لذلك لا يكفي أقصر مسار إلى الطعام، بل يجب تقييم البقاء والمساحة وسباق الخصوم معاً. [1]

## ما تغيّر في الإصدار 12

| المجال | التحسين المنفذ | الأثر المتوقع |
| --- | --- | --- |
| **سلامة الحركة** | فلتر حتمي للجدران، الأجسام، الضرر القاتل، واصطدامات الرأس بالرأس مع ثعبان مساوٍ أو أطول | يمنع النموذج أو الموزنات من اختيار حركة خاسرة معروفة مسبقاً |
| **نمذجة الذيل** | السماح بالذيل غير المكرر أن يفرغ، وحجبه عند تكرار الذيل بعد الطعام | مواءمة مع ترتيب حل الدور ومنع الاصطدامات الوهمية أو الحقيقية |
| **المساحة** | Flood Fill محدود بالمهلة، فحص ممرات، وتوقع قصير لتحرر الذيل | يقلل حبس الذات في الجيوب والممرات الضيقة |
| **المنافسة** | مساحة إقليمية تصل إليها قبل رؤوس الخصوم، سباقات الطعام، والافتراس الآمن للخصم الأقصر | يوازن بين البقاء والضغط بدلاً من المطاردة العمياء للطعام |
| **الرؤية** | الوضع القياسي يعامل كل المعلومات الواردة باعتبارها كاملة؛ ذاكرة الطعام ومناطق الشك لا تُفعَّل إلا عند وجود `viewRadius` | لا تُطبَّق افتراضات Blackout على مسابقة Standard |
| **الاستدلال المتعلم** | CNN خفيفة ذات رأسي Policy وValue في `neural_policy.py`، مدمجة بعد فلتر الأمان فقط | يمكن للنموذج تحسين التفضيل بين الحركات الآمنة دون تجاوز قواعد السلامة |
| **التدريب** | PPO مع GAE، تجمع خصوم تاريخي PFSP، ولقطات نماذج، وجمع مباريات متعدد العمليات اختياري | يقلل انهيار اللعب الذاتي ويدعم توسيع الدفعة إلى عشرات أو مئات المباريات بحسب العتاد |

## بنية القرار في المباراة

يبدأ `main.py` بتطبيع حمولة المباراة، بما في ذلك الحمولة الجزئية التي قد تحتوي مقاطع `None` في محاكي Blackout. ثم يُنشئ مرشحين للحركات الأربع ويمررها عبر ثلاث طبقات مرتبة. إن لم يبقَ أي خيار آمن مباشرة، يختار النظام «الأقل سوءاً»؛ أما في الحالة الطبيعية فلا يصل إلى هذا المسار.

| الطبقة | التنفيذ | قاعدة الأمان |
| --- | --- | --- |
| **1. قواعد غير قابلة للتفاوض** | `TacticalEngine._is_certain_death` | لا خروج عن اللوحة، لا دخول جسم، لا خطر يصفّر الصحة، ولا H2H متعادل/خاسر |
| **2. هامش النجاة** | Flood Fill وفحص تحرر الذيل | يفضّل مساحة كافية لجسم الثعبان بعد الحركة ولا يعامل الفشل المحافظ كوفاة مؤكدة |
| **3. المفاضلة الاستراتيجية** | مساحة، إقليم، غذاء، سباق غذاء، ذيل، موضع، خطر، وضباب عند وجوده | تُرتَّب الحركات الباقية، مع أولوية معجمية للغذاء عند الصحة الحرجة |
| **4. مستشار عصبي اختياري** | `NeuralAdvisor` | يضيف فقط ترتيباً بين الحركات التي مرت من الطبقات السابقة؛ عطل النموذج أو غيابه يعود تلقائياً للتكتيك |

## التثبيت والتشغيل

يتطلب خادم المباراة فقط الاعتماديات الخفيفة:

```bash
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

أو مباشرةً:

```bash
python3 main.py
```

يُرجع الجذر `GET /` هوية Battlesnake، بينما تستقبل المسارات `POST /start` و`POST /move` و`POST /end` الحمولة القياسية. حد الحساب الداخلي هو **200 ms** لإبقاء هامش أمام حد محرك المسابقة. لا توجد مكالمة شبكة أو تحميل نموذج داخل حلقة القرار بعد محاولة التحميل الأولى.

### الاستدلال بالنموذج المدرّب

احتفظ بالخادم التكتيكي وحده إلى أن ينجح النموذج في التقييم. بعد ترقية لقطة اختبارها، فعّلها بالمسار التالي:

```bash
export BATTLESNAKE_MODEL_PATH="$PWD/training/checkpoints/neural/champion.pt"
uvicorn main:app --host 0.0.0.0 --port 8000
```

إن كان PyTorch أو الملف أو شكل نقطة الحفظ غير صالح، يكتب الخادم تحذيراً واحداً ويكمل باستخدام المحرك التكتيكي. لا يجعل العطل الحركة غير صالحة ولا يسبب مهلة.

## التدريب باللعب الذاتي

تحتاج عملية التدريب — وليس الخادم — إلى الاعتماديات الاختيارية:

```bash
pip install -r requirements-training.txt
```

تشغّل التجربة القصيرة التالية PPO على محرك `hisss` الحقيقي وتُنشئ `training/checkpoints/neural/latest.pt`:

```bash
python3 training/neural_selfplay.py \
  --updates 10 --games-per-update 32 --epochs 4 --device auto
```

وعلى جهاز متعدد الأنوية يمكن توزيع **جمع الحلقات** فقط على عمليات CPU مستقلة؛ يُنفَّذ تحديث PPO على `--device` المحدد. لا تشغّل عمليات rollout متعددة على CUDA نفسها، لأن تنازع سياقات CUDA يضر الاستقرار والزمن بدلاً من تسريعه.

```bash
python3 training/neural_selfplay.py \
  --updates 200 --games-per-update 128 --workers 8 --epochs 4 --device cuda --resume
```

يستبقي `PrioritizedOpponentPool` الخصوم العشوائيين والتكتيكيين ولقطات الشبكة السابقة. يرّجح PFSP الخصم الذي تكون نسبة فوز المتدرب عليه قريبة من 50% باستخدام وزن متوازن مع حد أدنى موحّد؛ يحمي ذلك من نسيان الخصوم السهلة ويمنع التدريب من الاقتصار على خصم واحد. توجد دالة `solve_zero_sum_nash` لتحويل مصفوفة عوائد لقطات مقيمة إلى أولوية مختلطة، لكنها لا تدّعي أن مصفوفة عيّنة محدودة هي توازن Nash عالمي.

### دالة المكافأة

المكافأة `transition_reward` مشتقة فقط من حالتين متتاليتين من محرك اللعبة. لا توجد مكافآت مخفية من محاكٍ بديل.

| الحدث | المكافأة |
| --- | ---: |
| إقصاء الثعبان | **-1.000** (نهائية ودقيقة) |
| الفوز النهائي | +1.000 |
| البقاء في الدور | +0.010 |
| أكل طعام عند صحة ≤ 35 | +0.160 |
| أكل طعام عند صحة أعلى | +0.050 |
| زيادة الطول | +0.025 |
| الوقوف في Hazard | -0.035 |

تكون مكافأة الإقصاء النهائية هي المسيطرة، حتى لا يتعلم الوكيل التبادل بين موت مؤكد وغذاء أو طول إضافي.

## التقييم والترقية

لا تنشر `latest.pt` مباشرة. اختبره أولاً ضد تجمع الخصوم:

```bash
python3 self_play.py --checkpoint training/checkpoints/neural/latest.pt --games 64 --workers 4
```

ثم ثبّت اعتماديات الاختبار وشغّل اختبارات الشيفرة ومحاكيات الانحدار:

```bash
pip install -r requirements-dev.txt
pytest -q
python3 run_games.py --seed 8 --games 20 --no-hisss
```

الاختبار `test_seed8_regression.py` يمثل بوابة قبول مهمة؛ يرصد تحديداً الموت المبكر والقرار الذي يخفيه المحاكي باستبدال الحركة عند وقوع استثناء. يمكن أيضاً الوصول لمسار التدريب الجديد من واجهة المدرب القديمة حفاظاً على التوافق:

```bash
python3 training/train_blackout_elite.py --neural --updates 50 --games-per-update 64
```

مدرب `train_blackout_elite.py` من دون `--neural` يبقى مخصصاً لتجارب ضبط أوزان heuristic القديمة، وليس لتدريب الشبكة.

## معيار الترقية المقترح

لا توجد نتيجة محلية واحدة تثبت القوة في ترتيب المسابقة. اعتمد قراراً متحفظاً: ثبّت إعداد الخريطة وعدد اللاعبين والمهلة، وشغّل على الأقل عدة بذور ثابتة ودورة خصوم تشمل `tactical` و`random` ولقطات تاريخية. رقِّ النموذج فقط إن تجاوز النموذج السابق في نسبة الفوز مع عدم وجود انحدار في وفيات الاصطدام الذاتي أو p95 للزمن. احفظ جدولاً يذكر إصدار النموذج، البذور، الخصوم، عدد المباريات، نسبة الفوز، ومقاييس السلامة.

## الملفات الرئيسية

| الملف | المسؤولية |
| --- | --- |
| `main.py` | خادم FastAPI، مرشح النجاة، التكتيك، ودمج الاستدلال الاختياري |
| `neural_policy.py` | الترميز المكاني، CNN residual، masking قانوني، وحفظ/تحميل نقاط الحفظ |
| `training/neural_selfplay.py` | PPO + GAE، مكافأة القواعد، PFSP، snapshots، وجمع متوازٍ اختياري |
| `self_play.py` | تقييم نقطة حفظ ضد تجمع PFSP بدون تعديل النموذج |
| `training/train_blackout_elite.py` | مدرب الأوزان القديم مع بوابة توافق `--neural` |
| `tests/test_competitive_engine.py` | اختبارات الحمولة، الذيل، H2H، المكافأة، والمهلة |
| `test_seed8_regression.py` | اختبار انحدار محاكٍ للبقاء المبكر وزمن الحركة |

## ملاحظات مهمة للمسابقة

يجب مطابقة إعدادات المسابقة قبل التدريب: `width` و`height` وعدد اللاعبين و`hazardDamagePerTurn` ووجود `viewRadius` والمهلة الفعلية. يعمل المرّمز حتى لوحة 25×25؛ إذا كانت المسابقة أكبر من ذلك فلا تفعّل النموذج قبل إعادة تدريب encoder بحجم مناسب. كما أن MCTS لم يُدرج في مسار الخدمة الحالي عمداً: ألعاب Battlesnake متعددة اللاعبين ومتزامنة والحالة فيها خصوم بسياسات غير معروفة، لذلك البحث الضحل بلا نموذج انتقال للخصوم قد يستهلك مهلة القرار ويعطي ثقة زائفة. استُثمرت المهلة في مرشح أمان قوي وCNN اختياري، وهو مسار أكثر قابلية للقياس في هذا المستودع.

## استمرارية التدريب بين تشغيلات GitHub Actions

مسار **Daily Training Pipeline** يبقى يدويًا فقط. عند بدء تشغيل جديد يمكن ترك
`resume_run_id` فارغًا لبداية جديدة، أو إدخال رقم تشغيل سابق لاستعادة ملفاته
بدقة. الاستعادة تستخدم `GITHUB_TOKEN` القياسي بصلاحية قراءة Actions فقط، ثم
تتحقق من إصدار البيان، والبذرة، والملفات الإلزامية، وبصمات SHA-256 قبل تشغيل أي
مدرّب. إذا كان الأثر مفقودًا أو منتهي الصلاحية أو غير متوافق يفشل التشغيل بوضوح
ولا يبدأ تدريبًا جديدًا بصمت.

فحص سريع محلي بلا تدريب طويل:

```bash
python -m compileall -q training neural_policy.py test_continuity.py
python -m unittest -v test_continuity.py
python training/neural_selfplay.py --help
python training/train_hisss.py --validate-schema
```

كل تشغيل ناجح يرفع `continuity-manifest.json` مع نقاط التحقق والسجلات. يسجل
البيان commit وrun ID والبذرة وإعدادات المدرّبين ومصدر الاستعادة وإصدارات Python
والاعتماديات. مدة الاحتفاظ 30 يومًا؛ بعد انتهاء الأثر لا يمكن استئناف ذلك التشغيل.
للرجوع، شغّل يدويًا باستخدام `resume_run_id` لأثر صالح أقدم. لا يعدّل هذا المسار
`weights.json` ولا يروّج `latest.pt` أو `champion.pt` تلقائيًا.

نجاح الاستئناف لا يعني أن أداء الثعبان تحسن. يلزم لاحقًا تقييم مكرر ببذور وخصوم
محجوزين ومقارنة خط أساس قبل قبول أي نموذج، وتبقى المباريات العامة والنشر خارج M1.
